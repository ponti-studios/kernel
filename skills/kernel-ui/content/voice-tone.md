# UI Voice and Tone

Use this as the default interface-copy contract. A product may override it only
with a documented product profile.

## Voice

- Use short, direct sentences.
- Use plain verbs and concrete nouns.
- Use sentence case.
- State the action, result, or error first.
- Do not use hype, blame, filler, vague claims, or unexplained jargon.
- Write for translation: avoid concatenation, idioms, and embedded direction.

## Tone By State

| State | Rule |
| --- | --- |
| Routine | Neutral and concise |
| Onboarding | Specific and helpful; explain the next action |
| Success | State what completed; do not celebrate for the user |
| Error | State what happened, why when known, and how to recover |
| Destructive | State the consequence and require a clear action |
| High stress | Remove optional context and use the shortest actionable wording |

## Formulas

- Button: verb + outcome, such as `Save changes`.
- Confirmation title: question naming the action and object, such as `Delete account?`.
- Confirmation action: repeat the action and object, such as `Delete account`.
- Error: what happened -> why -> how to fix.
- Empty state: value -> first useful action.
- Label: name the field; do not put essential instructions in a placeholder.

## Pre-Ship Checklist

For every line, verify:

1. It reads naturally aloud.
2. Actions start with a verb and name the outcome.
3. Errors explain what, why, and how to recover.
4. Empty states provide value and a next action.
5. It uses sentence case and numerals consistently.
6. It contains no blame, hype, filler, or unexplained jargon.
7. It does not rely on color, direction, or position alone.
8. It fits the available character limit.
9. It can be translated without string concatenation.
10. It uses inclusive, concrete language.
