# Onboarding

**A user's first-day experience is the product's first proof that its promise is real.**

Use [[design]] to make the first useful action legible and [[voice]] to explain it without teaching jargon.

## Outcome standard

By the end of the first session, a new user should:

1. Understand who the product is for and what it helps them accomplish.
2. Complete one meaningful action related to that promise.
3. See enough evidence of future value to know what to do next.

An onboarding flow is not successful because a user finished a tour or created an account. It is successful when the user reaches value without requiring a human translator.

## Design sequence

### 1. Define the first useful outcome

Name the smallest completed action that demonstrates the product's promise. If the team cannot agree on this action, it is too early to design screens.

### 2. Remove the blank slate

Use a sample, template, starter project, import, or guided choice so users can see what is possible. Empty states should explain the next action, not merely announce that nothing exists.

### 3. Match context to intent

Signup friction should reflect the user's likely intent. Low-intent users need framing; high-intent users need a fast path. Do not optimize signup in isolation from the first-session experience.

### 4. Teach at the moment of need

Prefer clear defaults, progressive disclosure, and contextual guidance. In-product tours are a fallback, not a substitute for an intuitive product. Guidance must remain discoverable after dismissal.

### 5. Create the next commitment

End the first useful action with a concrete next step: invite someone, return at a specific time, complete a workflow, or explore a relevant capability.

## Research protocol

Test with someone unfamiliar with the product. Give them the same minimal context a real user receives, ask them to think aloud, and do not rescue them at the first hesitation. Record:

- What they think the product does.
- Where they hesitate or choose the wrong action.
- Whether they reach the intended outcome.
- What they believe they can do next.

Fix the largest comprehension failure before adding more guidance.

## Instrumentation

Track the sequence, not just the endpoint:

- signup completed
- first meaningful action started
- first meaningful action completed
- a-ha moment reached
- next-session intent expressed
- return visit within the chosen window

Pair these events with session observations. A high completion rate can still hide confusion, accidental success, or a weak promise.

## Anti-patterns

- Empty dashboards that ask users to invent the product's value.
- Tours that explain controls before the user has a reason to care.
- Guidance that disappears permanently after one click.
- Personalization that asks for information without changing the experience.
- Signup optimization that increases volume while lowering intent.

## First-session checklist

- Is the first useful outcome explicit?
- Can a new user discover it without a live explanation?
- Is there a concrete starting point rather than an empty slate?
- Does guidance appear at the moment of uncertainty?
- Can the team observe where users hesitate?
- Is the next action clear after value is delivered?
